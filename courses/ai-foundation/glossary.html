How to use the glossary

Read it once at the start of the course for vocabulary, then again before the final examination as a recall check. The Area column is deliberately precise: if you cannot connect a term to a syllabus area, you have not yet learned why it is being tested.

Vendor neutrality

The syllabus is deliberately vendor-neutral. Nothing in this course requires knowledge of a named commercial AI product: each definition describes a category of tool or a transferable technique. Where a demonstration is used, it must be framed around the category, never a brand, and never with real personal, confidential or commercially sensitive data.

Foundations, Domain 1

Artificial intelligence (AI) 1.1, The broad field of systems that perform tasks we associate with human intelligence. Most modern AI learns patterns from data to make predictions, generate content or take actions. It is not conscious, not infallible and not magic.

Rule-based system 1.1, A system that follows explicitly written rules rather than learning from data. A simple explanation of such a system can still be entirely accurate, simple is not the same as wrong.

Machine learning (ML) 1.2, A subset of AI in which the system learns patterns from data instead of being programmed with explicit rules. Every machine learning system is AI; not every AI system uses machine learning.

Deep learning 1.2, A subset of machine learning using many-layered neural networks. It powers most modern speech, vision and language systems.

Generative AI 1.2, A subset of deep learning that produces new content, text, images, audio, video or code, rather than only classifying or labelling what it is given.

Large language model (LLM) 1.2, A generative model trained on very large amounts of text, which produces output by predicting likely continuations. A subset of generative AI.

Narrow AI 1.3, A system designed for a specific task, capable within its domain but limited outside it. All commercial AI today is narrow AI.

General AI (AGI) 1.3, A hypothetical system able to perform any intellectual task a human can. It is a research goal, not a current product, useful as a test to apply to dramatic claims.

Mechanics, Domain 2

Model 2.1, A set of learned values (parameters), not a database of stored answers. It produces output by calculation, not by lookup.

Parameters 2.1, The adjustable values a model learns during training. At Foundation level, they are simply the values that shape the model's behaviour.

Training 2.1, The process of learning the model from a dataset, adjusting parameters until the model performs the task well.

Inference 2.1, Using a trained model to produce an output. Training happens once; inference happens every time you use the model.

Next-token prediction 2.2, How a language model generates text: it produces the most likely continuation given the prompt and the text so far. Output is generated, not retrieved.

Token 2.3, The basic unit of text a model reads and writes. Roughly a word fragment, a useful rule of thumb is that 100 tokens is about 75 words.

Context window 2.3, The model's short-term working memory: the amount of text it can consider at once. Exceed it and earlier detail is effectively forgotten.

Knowledge cut-off 2.4, The point after which the base model has no knowledge, because it was trained on data up to that date. Some applications add live search, but the base model remains frozen.

Temperature 2.5, The sampling setting that controls variability. Higher values give more varied output, which is why the same prompt can produce different answers.

Embedding 2.5, A representation of meaning as numbers, so that related items sit close together in that numerical space. Tested at awareness level only.

Landscape, Domain 3

Multimodal AI 3.2, AI that handles more than one type of input or output, for example text and images together.

Foundation model 3.2, A large, general-purpose model adapted to many different tasks rather than built for one.

Retrieval-augmented generation (RAG) 3.3, A technique that retrieves relevant sources and then generates an answer grounded in them. It improves freshness and grounding but reduces rather than removes error.

Agent 3.4, A multi-step, tool-using system that pursues a goal, as distinct from a single-turn assistant. Because agents take actions, they require greater human oversight.

Open-weight model 3.5, A model whose weights are available to run yourself. Trade-off: more control and data residency, but more setup and maintenance than a hosted service.

Working practice, Domains 4 and 5

Prompt 4.1, The instruction given to a model. The syllabus defines four components: task, context, format and constraints .

Zero-shot prompting 4.3, Asking for a task with no examples, relying on the model's existing capability.

Few-shot prompting 4.3, Providing one or more examples to calibrate style, format and tone. Use it when the output shape matters and is hard to describe in words.

Prompt chaining 4.4, Decomposing a complex task into ordered steps, each building on the last, instead of overloading a single prompt.

Iterative refinement 4.5, Treating the first output as a draft and improving it through specific, corrective follow-ups. Prompting is a conversation, not a single transaction.

Overloaded prompt 4.6, A prompt carrying several unrelated tasks at once, so the model does some of them poorly. The fix is to decompose.

Hallucination 6.1, Confident, fluent output that is factually wrong, with no signal that anything is amiss. It is inherent to how language models work, not an occasional bug.

Automation bias 8.3, The tendency to accept an automated suggestion because it is fluent and presented as an answer, especially under time pressure. Oversight fails here because the human was persuaded, not absent.

Security and data, Domain 7

Shadow AI 7.3, Unapproved AI use outside organisational oversight. A policy gap is a reason to escalate for approval, never a licence to proceed.

Prompt injection 7.5, Malicious instructions hidden in content the AI processes, for example in a document, a CV or a web page it is asked to read. Tested at awareness level: recognise it, do not exploit it.

Deepfake 7.4, Synthetic audio, video or imagery of a real person, generated by AI, used to mislead. Verify unexpected or urgent requests through a separate, trusted channel.

Data residency 7.2, Where data is physically stored and processed. Relevant because third-party AI services may transmit or store inputs according to their terms.

Governance, Domain 8

Bias 8.1, Systematic unfairness arising from three sources: training data (historical patterns), design choices (what is optimised), and deployment context (where and on whom it is used).

Proxy signal 8.1, A feature that carries protected information indirectly. Removing names does not remove the signal carried by institution, career gaps or postcode, so fairness must be tested on outcomes.

Explainability 8.2, Being able to give a meaningful account of how a decision was reached and what it was based on. It does not mean publishing source code or exposing model weights.

Human oversight 8.3, The principle that AI proposes while a person decides and owns the outcome. Meaningful oversight requires the information, authority, time and competence to disagree.

Accountability 8.2, The human or organisation remains answerable for the outcome. "The AI did it" is not a defence, because a system has no standing to answer.

Disclosure 8.4, Telling people when AI is used. Required where a rule demands it, where AI substantially generated the content, or where non-disclosure would mislead.

Professional decision framework 8.6, The four-outcome test applied to any AI use: use / use with verification / escalate / do not use, being more cautious when unsure.
