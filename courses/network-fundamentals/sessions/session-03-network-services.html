Core concepts

3A - DNS

DNS hierarchy: root, TLD, authoritative, recursive resolver. Record types: A, AAAA, CNAME, MX, NS, TXT, PTR. Attacks: cache poisoning (forged answers redirect users), tunnelling (data inside queries), amplification (spoofed small queries, huge responses). DNSSEC signs responses so forgery fails. Recursive resolvers should be restricted to internal clients - an open resolver is a public amplification tool that widens the attack surface. Distinguish spoofing (forging one reply) from poisoning (planting it in the cache for all users).

3B - DHCP

DORA: Discover, Offer, Request, Ack. T1 at 50% of lease triggers unicast renewal; T2 at 87.5% triggers broadcast rebind. Attacks: rogue servers assign malicious gateways/DNS (a man-in-the-middle chain); starvation exhausts the pool. Defence: DHCP snooping builds a MAC-to-IP-to-port binding table on the switch, and segmentation contains a rogue server to one segment.

3C - NTP

Stratum 0 atomic/GPS sources, stratum 1 servers, stratum 2 onward. UDP 123. Attacks: amplification via monlist (up to 100× response), spoofing to shift time. Mitigations: authenticated NTP (NTS), restricted access. Forensic rule: verify clock offset before acquiring evidence - minutes of offset corrupt timelines. Wrong clocks also break Kerberos ticket validation, so accurate time is infrastructure, not a convenience.

3D - SSH

TCP 22. Key exchange derives a shared session key without transmission. Key-based auth beats passwords - keys are never sent and resist brute force. Hardening: PermitRootLogin no, PasswordAuthentication no, LogLevel VERBOSE, AllowUsers, ClientAliveInterval. Verification: ss -tnp, journalctl -u ssh, grep sshd /var/log/auth.log. Hardening shrinks the attack surface: disabling password auth removes brute force as a threat class, and restricting users denies everyone else.

Practical cautions

Where marks are lost

  • Do not run an open recursive DNS resolver - it is a public amplification tool.
  • Do not leave the native VLAN or DHCP ports unguarded - both are entry points.
  • Do not trust a forensic timeline from a system whose clock was never verified.
  • Do not use password authentication for SSH when keys are available.
  • Do not ignore unexpected listening ports in ss -tuln - that is how compromise shows.
  • Do not let unnecessary services run - each one widens the attack surface.

Exam tips for Session 03

Security+ alignment

  • DNSSEC stops poisoning; DHCP snooping stops rogue servers - match the control to the attack.
  • NTP amplification and DNS amplification are both DDoS scenarios - know the mechanism.
  • SSH hardening settings appear in scenario questions - remember PermitRootLogin no.
  • The service-port table (22 SSH, 53 DNS, 67/68 DHCP, 123 NTP) is core knowledge.
  • Spoofing forges one reply; poisoning plants it in a cache - an exam-favourite distinction.
  • Reducing the attack surface is a stated security principle - closing unused services is an example.
