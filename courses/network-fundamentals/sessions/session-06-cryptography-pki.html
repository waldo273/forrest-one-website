Core concepts

3A - Cryptographic algorithms

Symmetric: one key, fast, bulk data, distribution problem. AES is the standard, with 128, 192 or 256-bit keys. Asymmetric: key pairs, solves distribution, slower, small payloads. RSA rests on factoring difficulty; ECC reaches similar strength with smaller keys, ideal for mobile and IoT. Key length: longer keys, larger keyspace, stronger against brute force. Hashing: one-way, fixed length, anti-collision and avalanche - integrity, not secrecy; SHA-256 or better, as MD5 and SHA-1 are broken. Digital signatures: hash + private key, verified with public key - integrity, authentication, non-repudiation.

3B - Public key infrastructure

CAs issue X.509 certificates binding public keys to identities; RAs verify identities before issuance. Trust flows from self-signed roots through intermediate CAs to leaf certificates, and trusting the root vouches for the whole chain. CSRs carry the public key (never the private key). CN is legacy; SAN is modern. Revocation: CRL lists vs OCSP real-time queries, part of the lifecycle of issuance, renewal, revocation and expiration. Key management: lifecycle, TPM/HSM cryptoprocessors, escrow with M-of-N control.

3C - Cryptographic solutions

Data at rest: full disk, file and database encryption. Data in transit: transport encryption (TLS, VPN) with perfect forward secrecy - an asymmetric handshake exchanges a symmetric session key, and ephemeral keys protect past traffic. Data in use: processed in memory. Passwords: salt + key stretching. Blockchain: blocks chained by hashes, tamper-evident. Obfuscation: steganography (least significant bits of images), tokenisation, data masking, code obfuscation.

Practical cautions

Where marks are lost

  • Do not use asymmetric for bulk data - symmetric is the bulk tool.
  • Do not rely on encryption for integrity - hashing does that job.
  • Do not treat a certificate as a safety rating - it proves key-to-identity binding.
  • Do not use MD5 or SHA-1 for anything modern - SHA-256 or better.
  • Do not store passwords without salt and stretching.
  • Do not confuse CRL with OCSP - one is a list, the other a real-time query.

Exam tips for Session 06

Security+ alignment

  • Job-fit is the exam skill: which algorithm, for which purpose.
  • Sign with private, verify with public - memorise the direction.
  • Data-state questions: at rest → disk/file; in transit → TLS/PFS.
  • Know CN vs SAN, CRL vs OCSP, TPM vs HSM - the exam loves pairs.
  • Recognise algorithms by role: AES symmetric, RSA and ECC asymmetric.
  • Remember salting defeats pre-computed tables; stretching raises guess cost.

Key terms

TermDefinition
Symmetric encryptionOne shared secret key encrypts and decrypts — fast, for bulk data
AESAdvanced Encryption Standard — symmetric; key sizes of 128, 192 or 256 bits
Asymmetric encryptionPublic/private key pair — public encrypts, private decrypts
RSA / ECCAsymmetric algorithms — RSA on factoring; ECC with smaller keys for constrained devices
KeyspaceThe range of possible key values; longer keys mean larger keyspaces
HashingOne-way, fixed-length digest — integrity and password storage; avalanche effect
Digital signatureHashing plus the private key — integrity, authentication, non-repudiation
PKIInfrastructure that proves the identity of a public key holder
Certificate authority (CA)Issues certificates to verified subjects
Registration authority (RA)Verifies identities before the CA issues
