Cryptography & Public Key Infrastructure

Symmetric and asymmetric encryption, hashing and digital signatures; the public key infrastructure of certificates, authorities and revocation; and the practical solutions for data at rest, in transit and in use.

3A3B3C

Learning outcomes

By the end of this session, candidates will be able to:

  • Explain symmetric encryption: one shared key, fast, suitable for bulk data, with a key-distribution problem; recognise AES and its 128, 192 and 256-bit key sizes.
  • Explain asymmetric encryption: public/private key pairs, with the public key easy to distribute and the private key secret; recognise RSA and ECC.
  • Explain key length and keyspace, and why longer keys resist brute force.
  • Describe hashing: one-way, fixed-length digests with anti-collision and avalanche properties, used for integrity and password storage (SHA-256 or better; MD5 and SHA-1 are broken).
  • Explain digital signatures: hashing plus the signer's private key, providing integrity, authentication and non-repudiation.
  • Describe PKI: certificate authorities, registration authorities, X.509 digital certificates, root of trust and chains.
  • Explain the certificate signing request flow and subject name attributes (CN versus SAN).
  • Describe certificate revocation via CRL and OCSP, and the certificate lifecycle.
  • Describe key management: lifecycle, TPM and HSM cryptoprocessors, and key escrow with M-of-N control.
  • Match cryptographic solutions to data states: at rest, in transit and in use.
  • Explain salting and key stretching, perfect forward secrecy, blockchain and obfuscation techniques (steganography, tokenisation, data masking, code obfuscation).

What this session is about

What this session covers, with teaching notes area by area.

3A — Cryptographic algorithms

Symmetric: one key, fast, bulk data, distribution problem. AES is the standard, with 128, 192 or 256-bit keys. Asymmetric: key pairs, solves distribution, slower, small payloads. RSA rests on factoring difficulty; ECC reaches similar strength with smaller keys, ideal for mobile and IoT. Key length: longer keys, larger keyspace, stronger against brute force. Hashing: one-way, fixed length, anti-collision and avalanche — integrity, not secrecy; SHA-256 or better, as MD5 and SHA-1 are broken. Digital signatures: hash + private key, verified with public key — integrity, authentication, non-repudiation.

3B — Public key infrastructure

CAs issue X.509 certificates binding public keys to identities; RAs verify identities before issuance. Trust flows from self-signed roots through intermediate CAs to leaf certificates, and trusting the root vouches for the whole chain. CSRs carry the public key (never the private key). CN is legacy; SAN is modern. Revocation: CRL lists vs OCSP real-time queries, part of the lifecycle of issuance, renewal, revocation and expiration. Key management: lifecycle, TPM/HSM cryptoprocessors, escrow with M-of-N control.

3C — Cryptographic solutions

Data at rest: full disk, file and database encryption. Data in transit: transport encryption (TLS, VPN) with perfect forward secrecy — an asymmetric handshake exchanges a symmetric session key, and ephemeral keys protect past traffic. Data in use: processed in memory. Passwords: salt + key stretching. Blockchain: blocks chained by hashes, tamper-evident. Obfuscation: steganography (least significant bits of images), tokenisation, data masking, code obfuscation.
