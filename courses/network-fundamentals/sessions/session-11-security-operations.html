Core concepts

11A - Monitoring

Sources: logs (security, system, application, network device, firewall), flow (NetFlow/sFlow), packet capture, sensors, and the SIEM that aggregates and correlates them. Baselines define normal; thresholds alert on deviation; alert fatigue buries real incidents. Pair real-time alerting with trend analysis and tune alerts to cut false positives.

11B - Incident response

Six phases: preparation (before!), detection and analysis (confirm, scope, classify, grade severity), containment (evidence trade-off), eradication, recovery (validated restores, intensified monitoring), lessons learned. Classify each incident and set severity low to critical to drive urgency. Close with an after-action review and root cause analysis so the incident cannot recur.

11C - Forensics

Evidence must be admissible and lawful to collect (warrant or consent). Chain of custody: every handover documented. Order of volatility: registers, RAM, then disk - memory forensics often reveals what logs miss. Preservation: use write blockers, image and hash before analysis, apply legal hold, retain logs. Techniques: carving, timeline analysis, hash analysis, metadata analysis.

11D - Indicators

Malware: viruses, worms, Trojans, ransomware, spyware, rootkits, botnets. Network: port scanning, unusual traffic, data exfiltration, C2 beacons. Application: web log probes, phishing email, privilege escalation, privilege usage at odd hours. Behavioural: repeated failed logins, unusual times, impossible travel, data spikes.

Practical cautions

Where marks are lost

  • Do not start response at containment - preparation comes first.
  • Do not treat every incident alike - classify it and grade its severity.
  • Do not skip the after-action review - lessons learned prevent recurrence.
  • Do not analyse the original drive - image and hash first.
  • Do not collect evidence without authorisation - warrant or consent first.
  • Do not ignore the order of volatility - RAM will not wait.
  • Do not celebrate 'service restored' - verify and monitor.
  • Do not let alert volume hide the real incident.

Exam tips for Session 11

Security+ alignment

  • Sequencing is the exam skill - phases and volatility order.
  • Chain of custody and order of volatility are guaranteed items.
  • Know SIEM aggregation and correlation - monitoring is scenario material.
  • Classify incidents and assign severity; the exam rewards this.
  • IoCs are scenario-based: read the pattern, name the indicator.
  • Alert fatigue and baseline questions are common monitoring items.
  • Authorisation (warrant or consent) and write blockers appear in forensic scenarios.

TermDefinition

Incident classificationType — unauthorised access, malware, DoS, data breach

ContainmentStopping the spread — isolate and segment
EradicationRemoving the cause from the environment

Root cause analysisFinding the underlying source so the incident cannot recur
Order of volatilityCapture the most volatile data first — RAM before disk
ImagingBit-for-bit copy — analyse the copy, preserve the original
Write blockerPrevents any change to the original data during examination
Legal holdPreserving records relevant to litigation

File carvingRecovering files from raw disk without the filesystem
